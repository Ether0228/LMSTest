# 学生周度反馈对外版字段契约（V1）

本契约对应 `student-weekly-feedback-v1` 单一 HTML 模板。网页预览与 Chromium PDF 使用完全相同的 HTML；固定板块不会因为本周数据稀疏而消失，而会显示“缺失”或“待确认”的中性状态。

## 固定可见板块与字段

| 板块 | 固定子板块 | Payload 字段 | 对外边界 |
| --- | --- | --- | --- |
| 报告元数据 | 学生、周次、周期、学期、智育师、版本 | `student`、`week`、`report` | 开场文案必须为人工确认事实 |
| 本周学习节奏 | 动态日期/时间透视、校区口径、参与汇总、图例、参与画面隐私说明 | `attendance.校区/出勤口径/days/slots/sessions` | 每条已确认学生场次即应参加场次；校区只决定读取线上或线下出勤事实，已有摄像头事实对所有学生保留；另一口径的空值不构成异常 |
| 课堂里发生了什么 | 每门课程场次数、实际内容、互动、问题与学校支持 | `courses[]` | 实际内容须 `actual_content_confirmed=true`；互动/问题/支持分别要求显式 `已确认` 状态 |
| 任务与学业进展 | Backlog（缺交/返工/待审）、任务明细 | `task_records[]` | Deadline 与状态由确定性规则产生；提交不等于完成，仅检查通过算完成 |
| 近期作业分数 | 多课程折线、肯定、关注、已确认原因、学校支持 | `grade_series[]` | 不表示课程总分趋势；原因只读取显式确认字段，不按分数猜测 |
| IELTS | 已确认目标、计划完成进度、未完成项、学校支持、计划明细 | `ielts_report` | 候选任务不进入计划；策略与支持须人工确认 |
| PBL | 已确认阶段、多里程碑、证据卡、AI review 候选状态 | `pbl_report` | AI review 不等于任务完成或阶段推进 |
| 下周共同推进 | 至少一条共同确认行动及学校支持 | `confirmed_next_actions[]` | 仅 `confirmation_status=已确认` |

## 模板覆盖与 fixture 完整度不是一回事

- **模板缺失**：固定子板块、字段绑定或中性空态不存在，会让真实数据即使到位也无法展示。这属于代码问题，需补模板和测试。
- **fixture 稀疏**：模板已有字段，但演示数据只覆盖少数日期、课程或任务。这属于演示覆盖问题，不能靠模板凭空补事实。
- `tests/fixtures/student_ops/week_v1.json` 是完整演示 fixture，用于覆盖全部固定板块；它不代表任何真实学生，也不建立新的学术规则。
- 生产数据缺失时，模板保留板块并显示缺数/待确认；不得用计划教学、AI候选或推断原因填空。

## 出勤口径

- `出勤口径`是依据`学生校区`配置产生的确定性字段，不由 AI 判断。
- 线上口径：单元格使用`线上出勤情况`；不展示线下教室，也不把线下“未记录”计为异常。
- 线下口径：单元格使用`线下出勤情况`和`线下出勤教室`；不展示线上出勤字段。
- 不论校区，只要`摄像头开启状态`有事实值就保留并呈现；字段为空只表示暂无记录。
- 摄像头字段为空只表示暂无记录，不得转译为“未开启”。未来场次不进入已确认出勤事实。

## Base → attendance payload 生产契约

- 生产输入是 `lark-cli base +record-list --format ndjson` 的 typed records；`pipeline/student_ops/attendance_adapter.py` 是唯一的 `days/slots/sessions` 生产适配器。手写 `attendance.days/slots/sessions` 只允许用于 fixture 和展示测试。
- 适配器先按 `学生学期 record_id + 周日期范围` 过滤`学生场次记录`，再用`学期场次` Link 的 record_id 连接上游。日期、时间、课程编码或场次类别任一不一致即报错，不静默选边。
- 透视格键为`上课日期 + 时间`；同格可保留多条学生场次，按日期、时间、Base record_id 稳定排序，不覆盖或合并事实。
- 当前真实 Base 没有独立的`是否应参加`、`场次状态/取消`、`原场次/调后场次`字段。因此适配器只输出`学生场次关系数`，将正式`应参加场次`分母设为 `null`，不计算 Attendance%。取消、调课及“无需出勤”是否排除分母仍需业务确认或字段证据。
- `as_of` 之后的记录一律标为 `future`；即使出勤格已预填，也不得当作已发生事实。已发生场次中，空值或线下默认值`未记录`均标为 `unrecorded`，不等于缺勤；摄像头空值不等于未开启。
- 当前校区映射来自真实 Base 已见值：`线上/线上校区 → 线上`；`北京、苏州、重庆巴渝、上海、广州、深圳、重庆西大 → 线下`。未知校区直接失败，等待配置确认，不按名称模糊猜测。
- 每个 session 同时生成 audit row：`学生场次 record_id/唯一键 → 学期场次 record_id → 透视格 → 最终显示文字`。
- 为诊断 `12:30-13:00 / 智育辅导`关系缺口，上游 NDJSON 必须同时投影目标校区字段（北京、苏州、重庆巴渝、重庆光环、上海、广州或深圳）。字段 key 未被投影时不等于 Base 单元格为空，适配器不会误报“校区未分配”。
- 上游存在智育辅导、目标校区字段为空且本学生无对应关系时，只输出 `upstream_campus_unassigned` 诊断和中性提示，不补造透视格。是否应分配仍由业务人员确认并在 Base 上游处理。

## HTML / PDF 同源约束

- `render_weekly_html()` 只调用 `render_weekly_report()`；`render_pdf()` 直接让 Chromium 打印已经写出的同一 HTML 文件，不存在 PDF 专用模板。
- `pipeline/build_weekly_attendance.py` 会从同一个 payload 一次生成 payload、audit、HTML 和 PDF；测试校验写出的 HTML 与发布快照中的 HTML 完全相等。
